# Безопасный стек
## Задача
Написать стек (просто две операции — push и pop) с защитами: канарейки на структуру стека и на данные, хеширование структуры и данных.

## Использование
### Настройки
```c
...
#define STACK_ALLOCATED_ENOUGH_CHECK // This check is only available with glibc
#define STACK_STRUCT_HASH_CHECK
#define STACK_BUF_HASH_CHECK
#define STACK_CANARY_CHECK
#define STACK_DEBUG
...
```

- `STACK_STRUCT_HASH_CHECK` — включает проверку целостности структуры через хеширование.
- `STACK_BUF_HASH_CHECK` — включает проверку целостности данных стека через хеширование.
- `STACK_CANARY_CHECK` — включает канареечные защиты структуры и данных.
- `STACK_ALLOCATED_ENOUGH_CHECK` — включает проверку достаточности размера аллоцированного сегмента памяти (использует нестандартную функцию `malloc_usable_size()` из расширения GNU).
- `STACK_DEBUG` — включает режим дебага.

### Режим дебаггинга
Все проверки работают через функцию `stack_status_code verify(stack_t *stack);`, которая возвращает отрицательную константу из `enum stack_status_code` в случае, если проверка не проходит. Вызывается `debug_stack_status_handler`, которая логирует ошибку и приостанавливает программу, ожидая реакции пользователя. Пользователь может по своему желанию продолжить выполнение, несмотря на ошибку.

**Если режим дебаггинга выключен, зафейленная проверка аварийно завершает программу.**

## Логирование
В файле `logging.c` можно настроить уровень логирования через раскомментирование соответствующего дефайна
```
// ------------Log_level_Settings----------------------------

// #define LOG_LEVEL_ERROR
// #define LOG_LEVEL_INFO
#define LOG_LEVEL_DEBUG

// ----------------------------------------------------------
```
Логи пишутся в файл `%d-%m-%Y-%H:%M.log` и в stderr.
